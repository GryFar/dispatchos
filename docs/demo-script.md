# DispatchOS — сценарий демо-видео для диспетчеров (сбор фидбека)

**Цель:** показать реальным диспетчерам рабочий поток + ИИ-фишки и собрать фидбек.
**Хронометраж:** ~6–8 мин. **Допущение:** упор на ИИ-«киллер»-фичи + базовый флоу; два портала (диспетчерский = «мозг», водительский = «руки») + «магия» превращения писем в грузы.

## Перед записью (подготовка)
- Аккаунт **диспетчера** с 2–3 назначенными карьерами и несколькими грузами.
- Аккаунт **водителя** (лучше owner-operator — покажешь и owner-инструменты).
- 2–3 «сырых» брокерских письма во входящих (для сцены с ИИ-парсингом).
- **ИИ включён** (`ANTHROPIC_API_KEY` задан) — иначе ИИ-кнопки отдадут «недоступно» (это корректная деградация, но для видео нужен живой результат).
- Телефон/эмулятор для водительского портала (он мобильный).

---

## Часть 1. Диспетчерский портал — «мозг» (≈3–4 мин)

### Сцена 1 — Кокпит `/dispatch`
**Показать:** три колонки — **Карьеры** (локация / HOS / алерты), **Топ-грузы**, **ИИ-предложения** (score + verdict `book/negotiate/skip` + backhaul-индикатор). Нажать **«AI analysis»** на карточке карьера → ИИ-рекомендация: reasoning + watch-outs + confidence.
**Говорить:** «Единый экран вместо десяти вкладок: слева все мои водители со статусом и алертами, в центре — лучшие доступные грузы, справа — ИИ уже спарил кого на какой груз и почему. Жму AI-анализ — получаю объяснение: почему этот груз и на что смотреть.»
**Спросить:** «Такой единый экран заменил бы ваши таблицы/чаты? Чего не хватает в первом взгляде?»

### Сцена 2 — Карточка груза + ИИ-ответ брокеру `/dispatch/loads/:id` ⭐ ключевая
**Показать:**
- маршрут, ставка, мили;
- блок брокера с **Trust Score** + быстрые сигналы (заплатил вовремя / срезал ставку / не отвечает / фрод);
- **карточку «Ответить брокеру»** → кнопка → **ИИ-черновик встречного оффера** (на основе ставки + нашей средней по полосе) → **Copy** / «Ещё вариант»;
- назначение водителя (диалог: выбор, статус, ёмкость, GPS).

**Говорить:** «По каждому грузу вижу брокера и его Trust Score — он собран из сигналов всех диспетчеров. Одна кнопка — и ИИ пишет готовый встречный оффер: вежливо, с обоснованием по нашей средней ставке на полосе. Копирую, правлю пару слов, отправляю. Тут же назначаю водителя — с защитой от двойного бронирования.»
**Спросить:** «ИИ-черновик реально сэкономил бы время на переписке? Тон ок? Что бы поправили перед отправкой?»

### Сцена 3 (опц.) — Предсказания и очередь `/dispatch/predictions`, `/dispatch/queue`
**Показать:** watchlist по полосам + предсказания; очередь задач на подтверждение.
**Говорить:** «Ставлю полосу на слежение — система пингует, когда появляется подходящий груз, не надо мониторить вручную.»

---

## Часть 2. Водительский портал — «руки» (≈2–3 мин, с телефона)

### Сцена 4 — Дашборд водителя `/d`
**Показать:** статус (свободен / в рейсе / off-duty), сегодняшние грузы, крупные кнопки.
**Говорить:** «Водитель видит только своё: статус, назначенные грузы, кнопки под большой палец.»

### Сцена 5 — Груз водителя: чек-ины, документы, чеки `/d/loads/:id` ⭐
**Показать:** таймлайн чек-инов (прибыл на погрузку → загружен → в пути → доставлен); загрузка документов (BOL/POD); расходы + **скан чека** (ИИ-OCR вытаскивает сумму/дату).
**Говорить:** «Один тап — и статус ушёл диспетчеру вживую. Сфоткал чек — ИИ сам достаёт сумму и дату в расходы и IFTA. Никакого ручного ввода.»
**Спросить:** «Водители реально будут жать чек-ины? Что упростить, чтобы жали?»

### Сцена 6 — Owner-operator инструменты `/d/owner/*`
**Показать:** scored-борд со **своим ИИ-советником**; **broker-check** (Trust по MC); **detention**-калькулятор; **IFTA**-отчёт (+CSV).
**Говорить:** «Владелец-оператор получает мини-диспетчера в кармане: ИИ-подбор грузов, проверка брокера, детеншн, IFTA — без найма отдельного диспетчера.»

---

## Часть 3. Магия под капотом (≈1 мин)

### Сцена 7 — Входящая почта → груз `/admin/email-inbox`
**Показать:** ленту входящих брокерских писем с бейджем **parsed / not-parsed**; открыть письмо → сырой текст + распарсенный JSON.
**Говорить:** «Брокеры шлют офферы письмами в любом формате. Система парсит их в структурированные грузы; где обычный парсер спотыкается — подключается ИИ и достаёт поля. Диспетчер получает готовый груз, а не копипастит из почты.»
**Спросить:** «Сколько офферов в день приходит вам почтой и в каком виде?»

## Вопросы для фидбека (финал видео)
- Что из показанного закрыло бы вашу реальную боль №1?
- Чему бы **не** доверили ИИ — подбору, переписке или парсингу?
- Чего критически не хватает для ежедневной работы?
- За что из этого готовы платить?

# Список API (по экранам)

⭐ = ИИ / ключевое для демо. Пути с `:id` / `:mc` — параметр в URL.

## Диспетчер (`/api/dispatch/*` + ИИ + broker-trust)
- `GET /api/dispatch/cockpit` ⭐ — данные кокпита (карьеры, топ-грузы, ИИ-предложения)
- `POST /api/dispatch/ai-recommend` `{clientId}` ⭐ — ИИ-советник по карьеру
- `POST /api/dispatch/ai-credits/purchase` `{clientId}` — докупка ИИ-кредитов (per-carrier)
- `GET /api/dispatch/me/dashboard` — дашборд диспетчера
- `GET /api/dispatch/loads` — список грузов
- `GET /api/dispatch/loads/:id` — карточка груза
- `GET /api/dispatch/loads/:id/checkins` — таймлайн чек-инов
- `PATCH /api/dispatch/loads/:id` — назначить/переназначить водителя (бронь, anti-double-book)
- `GET /api/dispatch/clients` — назначенные карьеры
- `GET /api/dispatch/clients/:id/drivers` — водители карьера
- `GET /api/dispatch/predictions` — предсказания
- `GET/POST/PATCH/DELETE /api/dispatch/watchlist[/:id]` — слежение за полосами
- `GET/POST /api/dispatch/approval-tasks[/:id]` — очередь подтверждений
- `POST /api/ai/draft-broker-reply` `{loadId}` ⭐ — ИИ-черновик ответа брокеру (Task-3)
- `GET /api/broker-trust/:mc` — Trust Score брокера
- `POST /api/broker-trust/signal` `{brokerMc, loadId, signalType, positive}` — сигнал доверия
- `GET /api/ai-quota` — остаток ИИ-квоты (бейдж)

## Водитель (`/api/me/*`)
- `GET /api/me` — текущий пользователь (auth)
- `GET /api/me/dashboard` — дашборд водителя
- `GET/POST /api/me/status` — статус (свободен/в рейсе/off-duty)
- `GET /api/me/loads` — мои грузы
- `POST /api/me/loads` — создать груз (owner-op self-dispatch)
- `GET /api/me/loads/:id` — карточка груза
- `GET /api/me/loads/:id/checkins` — таймлайн чек-инов
- `POST /api/me/loads/:id/checkin` — отметить чек-ин (погрузка/загружен/в пути/доставлен)
- `GET /api/me/loads/scored` ⭐ — owner-op scored-борд
- `POST /api/me/loads/ai-recommend` ⭐ — owner-op ИИ-советник
- `GET/POST /api/me/documents`, `DELETE /api/me/documents/:id` — документы (BOL/POD)
- `GET/POST /api/me/expenses` — расходы
- `POST /api/me/expenses/scan-receipt` ⭐ — ИИ-OCR чека (сумма/дата)
- `POST /api/me/issues` — сообщить о проблеме по грузу
- `GET/POST /api/me/fuel` — топливные транзакции
- `GET /api/me/ifta`, `GET /api/me/ifta.csv` — owner-op IFTA
- `GET /api/me/detention` — детеншн-калькулятор
- `GET /api/me/broker-trust/:mc` ⭐ — owner-op broker-check
- `GET/PATCH /api/me/profile` — профиль
- `PATCH /api/me/preferences` — язык интерфейса
- `POST /api/me/ai-credits/purchase` — докупка ИИ-кредитов
- `POST /api/me/telegram/link-code` — привязка Telegram-бота
- `GET/PATCH /api/me/onboarding` — онбординг

## GPS-трекинг
- `/api/track/*` — пинг локации водителя (по tracking-token, отдельный контур)
- `GET /api/admin/users/:id/track`, `.../tracking-token` — карта локации в админке/кокпите

## ИИ-ядро (сводка «killer»-фич)
- **Парсинг письма → груз** — фоновый (cron-поллер → `parseBrokerEmailWithAi`); UI-точка просмотра: `GET /api/admin/email-ingest` ⭐
- **Диспетч-советник** — `POST /api/dispatch/ai-recommend` ⭐
- **Owner-советник** — `POST /api/me/loads/ai-recommend` ⭐
- **Ответ брокеру** — `POST /api/ai/draft-broker-reply` ⭐
- **OCR чека** — `POST /api/me/expenses/scan-receipt` ⭐
- **Квота/докупка** — `GET /api/ai-quota`, `POST /api/me/ai-credits/purchase`, `POST /api/dispatch/ai-credits/purchase`
- Рычаги стоимости ИИ (для инфры, не для демо): `DISPATCHOS_AI_KILL`, `DISPATCHOS_AI_GLOBAL_DAILY_CAP`, `DISPATCHOS_AI_PARSE_DAILY_CAP` (см. `docs/runbooks/AI-CONTOUR.md`)

## Auth / общие (нужны, чтобы вообще войти)
- `POST /api/auth/{login, signup, logout, forgot-password, reset-password}`
- `POST /api/auth/totp/*`, `/api/auth/phone/*`, `/api/auth/email/*` — 2FA / коды
- `GET /api/me`, `GET/PATCH /api/me/onboarding`, `GET /api/onboarding/mc-lookup` (FMCSA)
- `GET /api/public/pricing`, `GET /api/billing/{status, plan}`, `POST /api/billing/{checkout, portal}`
- `GET /api/telegram/bot-info`

## Админ / инфра (не показываем диспетчерам, но задействованы)
- `POST /api/inbound/email` — вход писем от Cloudflare Email Worker
- `GET /api/admin/email-ingest`, `/api/admin/load-sources[/*]` — источники грузов
- `/api/admin/clients[/*]`, `/api/admin/loads/:id`, `/api/admin/billing/*`, `/api/admin/integrations[/*]`
- `POST /api/cron/*` — планировщики (poll-load-sources, rescore, pickup-reminders, billing, backup…)

---
_Примечание: пути диспетчерских и водительских роутов собраны с клиента (что экраны реально зовут). ИИ-фичи, отмеченные ⭐, без ключа отдают 503/«недоступно» — для демо ключ обязателен._
